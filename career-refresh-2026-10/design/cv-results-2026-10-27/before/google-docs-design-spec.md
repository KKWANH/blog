# Google Docs 제작용 CV 디자인 명세

현재 시안: `portfolio-cv-signature-final`. 실제 HTML A4 레이아웃과 이 문서는 같은 `editorial-design.json` / `editorial-content.json`에서 생성합니다. 시각 자료는 `http://localhost:3100/studio/cv-editorial-2026-10-27/index.html`에서 확인합니다.

붙여넣을 영어 본문은 같은 데이터로 생성한 `editorial-copy.md`에 있습니다. 미리보기의 Copy CV text 버튼으로도 복사할 수 있습니다.

## 디자인 방향

세리프 이름과 큰 초록 직함의 대비를 주된 디자인 포인트로 사용합니다. 명함과 연결되는 작은 창 모양, 정렬선과 구획이 일관된 인상을 만듭니다. 경력은 회사·역할·날짜·근거를 나누어 읽히게 하고 본문을 장식으로 채우지 않습니다.

## 1. 실제 지면과 여백

- A4 세로, 210 × 297mm, 흰색.
- 좌우 18mm, 위 15mm, 아래 16mm.
- 본문 폭 174mm. 왼쪽 정렬.
- Google Docs에서 페이지 모드, 인쇄 레이아웃과 눈금자를 켭니다.

## 2. 서체와 크기

| 요소 | 서체 | 크기 | 굵기 | 색 |
| --- | --- | --- | --- | --- |
| 이름 | Source Serif 4 | 30pt | Regular 400 | `#1C2922` |
| 머리말 직함 | Inter | 24pt | Medium 500, 없으면 Regular | `#416E50` |
| 회사 | Inter | 12.5pt | Semibold 600 | `#1C2922` |

Docs의 글꼴 더보기에서 Source Serif 4와 Inter 제공 여부를 확인합니다. 사용할 수 없으면 이름은 Georgia Regular, 본문은 Arial로 통일하고 줄바꿈을 다시 확인합니다. HTML의 미세한 자간은 Docs에서 똑같이 지정할 수 없으므로 공백 문자로 흉내 내지 않습니다.

## 3. 머리말

이름은 왼쪽의 30pt Source Serif 4 Regular, 바로 아래 Software Engineer는 24pt Inter Medium, `#416E50`로 둡니다. 이름과 큰 직함의 대비가 시각적 포인트입니다. 실제 회사별 직함은 본문에서 유지합니다.

오른쪽 위에는 약 8mm 크기의 글자 없는 두 칸 창 모양을, 그 아래에는 9.5pt 보조색으로 `Systems & interfaces` / `Integration · C++`를 두 줄로 정렬합니다. 화살표나 클릭 버튼 모양으로 만들지 않습니다.

Docs에서는 테두리 없는 2열 표(약 112mm/62mm)로 이름·직함과 기호·보조문구를 배치하고, 연락처 한 줄은 표 아래에 둡니다. 연락처는 9.5pt이며 `Leuven, Belgium`, `kwanho0096@gmail.com`, 웹사이트, LinkedIn, GitHub입니다. 이메일·웹·프로필 링크에는 가는 밑줄을 적용합니다. 아래 구분선은 약 0.5pt `#B4C3B4`입니다.

## 4. 경력과 날짜

회사명은 12.5pt Semibold로 독립된 행에 두고, 날짜를 같은 행의 오른쪽에 맞춥니다. 직함은 다음 행에서 11pt Medium으로, 팀/위치는 그 뒤에 9.5pt 보조색으로 둡니다. Docs에 해당 굵기가 없으면 Bold/Regular로 두 단계만 사용합니다. 날짜 탭은 왼쪽 본문 기준선에서 174mm 위치입니다. 공백 여러 개로 정렬하지 않습니다.

강조는 lifter fault recovery, Python WebSocket client, V2X demonstrator 같은 실제 작업 구절에만 제한합니다. HTML은 Medium 500을 사용합니다. 문장 전체를 굵게 만들지 않습니다.

경력 사이의 간격은 9pt, 섹션 앞은 10.5pt입니다. 본문은 11pt / HTML 기준 14.5pt 줄 간격입니다. Docs의 배수 간격은 글꼴 메트릭의 영향을 받으므로 1.15~1.2에서 시작해 화면과 인쇄 결과를 보며 조정합니다. 줄 간격 입력란에 `14.5`를 배수로 넣지 않습니다.

불릿은 실제 목록으로 만들고 글 시작을 약 3.8mm 들여씁니다. 두 번째 줄은 첫 단어에 맞춥니다. 회사·팀/위치 행은 다음 단락과 함께 유지하고, 각 불릿은 줄을 함께 유지합니다.

## 5. 기술 영역

아래 내용을 실제 텍스트로 유지합니다. 라벨만 Bold로 둡니다.

```text
Languages: C++, C, Python; TypeScript, JavaScript
Systems: Error recovery; interfaces; WebSocket / REST; ROS 1/2
Tools & UI: Git, Docker, Linux, Qt/QML, React; Figma (basic UI)
```

기술 영역은 채운 상자 없이 세 칸으로 나눕니다. Docs에서는 3열 1행 표에 위아래 약 0.65pt `#B4C3B4` 선과 칸 사이 0.5pt 세로선만 두고, 외곽 좌우 테두리와 배경색은 제거합니다. 제목은 9.5pt Semibold, 내용은 10.5pt / 14pt입니다. 아이콘은 추가하지 않습니다.

Languages는 `C++, C, Python;` / `TypeScript, JavaScript` 두 줄을 의도적으로 나눕니다. Figma의 기본 UI 경험이라는 범위를 유지합니다.

## 6. 프로젝트와 학력

프로젝트명과 공개 저장소 링크를 연결하고, 본인 기여와 팀 수상 범위를 함께 적습니다. BCX 수상은 digital.auto & mobility challenge의 1위입니다. C++ containers는 42 프로젝트로 표시하며 vector, stack, AVL 기반 map과 iterator라는 실제 코드 범위로 설명합니다. 새 테스트를 통과했다고 주장하지 않습니다. Ariadne는 CV에서 제외합니다.

현재 프로젝트 부분은 왼쪽 38mm에 이름/맥락, 오른쪽에 기여 설명을 둡니다. 간격은 5mm입니다. Docs에서는 두 행의 테두리 없는 표로 재현할 수 있으며, 복사·내보내기 뒤 각 프로젝트의 제목과 설명 순서를 확인합니다.

학력은 학위 취득과 진행 중 상태를 구분합니다. Computer Engineering과 Business Administration은 같은 기관 아래 각각의 취득 연도와 함께 묶습니다.

42와 SEA:ME는 각각 독립된 교육 항목으로 둡니다. HTML에서는 두 열에 나란히 배치하되 각 프로그램의 이름·내용·수료 상태를 따로 표시합니다. Docs에서는 마지막 교육 부분에만 테두리 없는 2열 표를 사용하거나 두 문단으로 분리할 수 있습니다.

현재 프로그램 이름은 10.5pt Semibold입니다. 학위 항목과 프로그램 사이에 0.5pt의 옅은 선과 짧은 여백을 두어 서로 다른 자격임을 구분합니다.

- **42 — Software engineering:** Seoul / Wolfsburg · Completed. 수료 날짜는 제공되지 않았으므로 만들지 않습니다.
- **SEA:ME — Automotive & Mobility:** Jul 2023–Jun 2024 · Completed.

학위와 프로그램 수료를 같은 자격으로 표현하지 않습니다.

## 7. 마무리

본문을 먼저 완성한 뒤 이름, 회사, 섹션 제목 스타일을 적용합니다. 넘치면 반복 표현과 선택 항목을 줄이고 간격을 조정합니다. 11pt 본문을 더 작게 줄여 한 페이지에 억지로 맞추지 않습니다.

HTML/PDF 검토 결과는 별도 리뷰 기록에 남깁니다. 실제 Google Docs 조판·내보내기·ATS 처리는 아직 검증한 것이 아닙니다. 링크와 복사된 텍스트 순서를 확인하고, 글꼴이 바뀌면 페이지 수를 다시 확인합니다.
